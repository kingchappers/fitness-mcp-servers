# mcp-hevy Design

Date: 2026-09-12

## Overview

Add a third MCP server, `mcp-hevy`, giving Claude read access to Hevy
(strength training log) data — workouts, routines, exercise history, and
body measurements — following the same server pattern as `mcp-garmin` and
`mcp-myfitnesspal`.

## API Summary (Hevy Public API)

- Base URL: `https://api.hevyapp.com`
- Auth: single `api-key` header (UUID string), generated by the user at
  `https://hevy.com/settings?developer`. No login flow, no token/cookie
  refresh — simpler than either existing server.
- Pagination: `page` (default 1) / `pageSize` (default 5) query params on
  list endpoints.
- Scope: **read-only**. The API also exposes POST/PUT endpoints (create
  workout, update routine, create body measurement) but this server does
  not implement them — consistent with `mcp-garmin`/`mcp-myfitnesspal`,
  which never write back to the source system.

## Auth & Client

- Env var: `HEVY_API_KEY` (no `.env` support — set directly in the MCP
  client config's `env` block, same as `GARMIN_EMAIL`/`MFP_COOKIE_PATH`).
- `client.py` builds an `httpx.Client` with `base_url="https://api.hevyapp.com"`
  and the `api-key` header preset, exposed via a module-level
  `get_client()` singleton (mirrors `mcp_garmin.client.get_client`).
- No `scripts/login.py` — nothing to interactively authenticate. README
  documents generating the key on hevy.com and setting the env var.
- Missing/invalid key: `get_client()` raises `RuntimeError` with a message
  pointing at `HEVY_API_KEY`, caught by `server.py`'s existing
  `RuntimeError` handler (same pattern as Garmin's missing-token-store
  error).

## Tools

| Tool | File | Parameters | Hevy endpoint |
|------|------|-----------|----------------|
| `get_workouts` | `workouts.py` | `page`, `page_size` (optional, default 1/5) | `GET /v1/workouts` |
| `get_workout_count` | `workouts.py` | none | `GET /v1/workouts/count` |
| `get_workout` | `workouts.py` | `workout_id` | `GET /v1/workouts/{workoutId}` |
| `get_routines` | `routines.py` | `page`, `page_size` | `GET /v1/routines` |
| `get_routine` | `routines.py` | `routine_id` | `GET /v1/routines/{routineId}` |
| `get_routine_folders` | `routines.py` | `page`, `page_size` | `GET /v1/routine_folders` |
| `get_exercise_templates` | `exercises.py` | `page`, `page_size` | `GET /v1/exercise_templates` |
| `get_exercise_template` | `exercises.py` | `exercise_template_id` | `GET /v1/exercise_templates/{exerciseTemplateId}` |
| `get_exercise_history` | `exercises.py` | `exercise_template_id` | `GET /v1/exercise_history/{exerciseTemplateId}` |
| `get_body_measurements` | `body.py` | `page`, `page_size` | `GET /v1/body_measurements` |
| `get_user_info` | `user.py` | none | `GET /v1/user/info` |

Not implemented: `POST /v1/workouts`, `PUT /v1/workouts/{id}`,
`GET /v1/workouts/events` (sync-cache helper, not conversationally
useful), `POST /v1/routines`, `PUT /v1/routines/{id}`,
`POST /v1/exercise_templates`, `POST /v1/routine_folders`,
`GET/POST/PUT /v1/body_measurements/{date}` (redundant with the list
endpoint for conversational use).

## Response Size Policy

Per `CLAUDE.md`, verify real sizes with a live `HEVY_API_KEY` before
finishing:

- `get_workout` / `get_workouts`: workouts embed full per-set data
  (weight, reps, RPE per set, per exercise) — check with a real workout
  containing several exercises; add `_summarize_workout` if any single
  workout response exceeds 20 000 chars.
- `get_exercise_history`: could grow long for exercises logged over years;
  check size with a well-used account and consider whether it needs a
  page/limit parameter.
- All other endpoints (routines, folders, templates, body measurements,
  user info, count): expected small based on the OpenAPI schema: no time
  series data, default `pageSize` is 5. Verify but no summarization
  expected.

## Error Handling

Same shape as `mcp_garmin.server.call_tool`:
- `RuntimeError` (missing/invalid API key) → returned as `TextContent`,
  logged as auth error.
- `ValueError` (validation failure) → returned as `TextContent`, logged
  as validation error.
- `httpx.HTTPStatusError` (4xx/5xx from Hevy) → caught in `client.py`
  helper and re-raised as `RuntimeError` with the status code and Hevy's
  error body, so it surfaces through the same `RuntimeError` branch.
- Any other exception → generic catch-all, matches existing servers.

## Key Decisions

| Decision | Choice | Reason |
|----------|--------|--------|
| Scope | Read-only | Matches existing servers; avoids write-payload validation surface |
| Auth storage | MCP config `env` block, no `.env` | Consistent with `GARMIN_EMAIL`/`MFP_COOKIE_PATH`; no new dependency (python-dotenv) |
| HTTP library | `httpx` | Already a transitive dependency (mcp SDK); no login/cookie complexity needed unlike Garmin/MFP |
| Excluded endpoints | Skip write endpoints, `/workouts/events`, per-date body measurement endpoints | Out of scope for conversational read access; redundant with list endpoints |
